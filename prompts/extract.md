# 提取任务

从下面的执行日志段落中提取 GTD 清单条目。

## 输出格式

以 JSON 格式输出，格式如下：

```json
{
  "items": [
    {
      "title": "条目标题（短语即可）",
      "description": "条目描述（提取关键信息，简洁）",
      "category": "下一步行动 | 等待回复 | 悬而未决 | 日程",
      "priority": "高 | 中 | 低",
      "needs_discussion": false
    }
  ]
}
```

## 分类规则

- **日程**：有明确日期/时间安排的事项
- **下一步行动**：自己可以推进的具体任务
- **等待回复**：需要等待他人回应的事项
- **悬而未决**：有想法但尚未决定如何推进，或需要进一步思考的事项

## 优先级规则

- **高**：重要且紧急，或对业务有重大影响
- **中**：重要但不紧急，或常规工作
- **低**：想法性质、探索性质，或时间上不紧迫

## 时间感知（重要）

日志段落按时间顺序排列，同一篇日志可能包含「计划 → 执行 → 已完成」的演进。

判别规则：
1. **看时态**：过去时 / "已..." / "...过了" → 已完成的动作，不应列为待办
2. **看上下文**：段落靠前可能是计划，靠后可能是结论。如果日志后续段落明确说某件事"已经做完了"，则跳过前面对应的计划
3. **看意图**：纯观察/结论/感慨 → 不是待办
4. **不确定的**：标记 needs_discussion 为 true，不要擅自跳过

## 注意事项

- 默认收录所有可能的事项，不确定时标记 needs_discussion 为 true
- 包含业务拓展、获客等事项（不限于内部团队协作）
- 一条日志段落可能包含多个条目，也可能没有条目
- 标题要具体，便于后续识别和追踪
