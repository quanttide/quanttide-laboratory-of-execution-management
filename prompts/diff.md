# 比对任务

将提取的候选条目与现有的 GTD 清单进行比对，输出结构化变更指令。

## 比对规则

1. **新增**：候选条目在现有清单中找不到语义相似的内容，且确实是新的待办项
2. **合并**：候选条目与现有条目语义相关，提供了新信息 → 更新现有条目的描述或优先级
3. **跳过**：候选条目与现有条目语义相同，或已在清单中 → 忽略
4. **待讨论**：不确定如何处理，或与现有条目有重叠但又不完全一致

## 输出格式

以 JSON 格式输出，不要输出 Markdown 全文。

```json
{
  "additions": [
    {
      "category": "下一步行动",
      "title": "条目标题",
      "description": "条目描述",
      "priority": "中"
    }
  ],
  "merges": [
    {
      "category": "日程",
      "target_title": "现有条目标题",
      "new_description": "合并后的描述",
      "new_priority": "高"
    }
  ],
  "discussions": [
    {
      "category": "下一步行动",
      "title": "条目标题",
      "reason": "为什么标记待讨论"
    }
  ]
}
```

## 注意事项

- additions 中的 category 只能是：日程、下一步行动、等待回复、悬而未决
- merges 中的 target_title 必须是清单中已有的条目标题（精确匹配）
- 如果没有任何变更，输出空数组即可
- 不要输出不属于待办的内容
