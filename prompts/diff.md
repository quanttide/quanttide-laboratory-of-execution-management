# 比对任务

将提取的候选条目与现有的 GTD 清单进行比对，输出结构化变更指令。

## 比对规则

按以下优先级依次判断：

1. **合并**：候选条目与某现有条目**语义相同或高度相关** → 更新现有条目的描述或优先级，不新增
2. **跳过**：候选条目与现有条目完全重复，或已在清单中以不同措辞覆盖 → 忽略
3. **新增**：候选条目在现有清单中找不到任何语义重叠 → 添加到对应板块
4. **待讨论**：候选条目与现有条目有部分重叠但不确定如何合并 → 标记待讨论

**合并规则**：不要只看标题精确匹配。语义相近即可合并。例如"关注 icecoder issue 进展"与现有"icecoder CLI 输出改善"是同一件事的不同表述，应合并而非新增。

## 输出格式

以 JSON 格式输出，不要输出 Markdown 全文。

```json
{
  "additions": [
    {
      "category": "下一步行动",
      "title": "条目标题",
      "description": "条目描述",
      "priority": "中"
    }
  ],
  "merges": [
    {
      "category": "日程",
      "target_title": "现有条目标题",
      "new_description": "合并后的描述",
      "new_priority": "高"
    }
  ],
  "discussions": [
    {
      "category": "下一步行动",
      "title": "条目标题",
      "reason": "为什么标记待讨论"
    }
  ]
}
```

## 注意事项

- additions 的 category 只能是：日程、下一步行动、等待回复、悬而未决
- merges 的 target_title 与现有条目做**语义匹配**，不必精确一致
- 优先使用 merge，减少不必要的 additions
- 如果没有任何变更，输出空数组即可
